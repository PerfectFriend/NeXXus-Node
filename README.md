## 🌌 Концепция: Кибернетический Периметр и Цифровая Крепость

**NeXXUs** — это программно-аппаратный комплекс нового поколения, созданный для **автономной круглосуточной охраны физических и цифровых объектов**, изолированных хранилищ, распределённых складов и суверенной инфраструктуры без единой точки отказа (SPOF).

Проект объединяет в себе:
1. **Эстетику органической биоморфной защиты Гауди**: пластичные, самовосстанавливающиеся структуры сетевого роя, повторяющие природные законы децентрализации и прочности параболических сводов.
2. **Экспрессию космической бдительности Ван Гога**: непрерывный вихревой поток зашифрованной телеметрии, динамический аудит целостности и радиочастотное сканирование окружения.
3. **Бескомпромиссную мощь Киберпанка**: автономные сторожевые демоны (Sentinels), лучевые трипвайры, анонимные маршруты Tor v3, аппаратные watchdog-системы и криптографические доказательства владения (Proof-of-Retrievability).

Никакие внешние облачные корпорации, государственные реестры или закрытые провайдеры не имеют ключей к вашему периметру. **Ваш объект защищён математикой, криптографией и суверенным роем независимых сторожевых узлов.**

### 1. Автоматическая Охрана Объектов и Периметра
- **Сторожевые узлы (Sentinel Nodes)**: автономные демоны под Linux, Android и промышленные SBC (Raspberry Pi, Orange Pi), непрерывно контролирующие вверенные секторы и сигнальные датчики.
- **Анти-Аутсорсинг и проверка физического присутствия (Local I/O Latency Verification)**:
  - Специализированный математический протокол замера локальной задержки дискового и аппаратного отклика ($\Delta t < 50$ мс).
  - Узел физически обязан находиться на охраняемом объекте. Попытка перенаправить телеметрию в удалённое облако (AWS/Hetzner) мгновенно дисквалифицирует узел по таймауту локального I/O.
- **Анализ разнообразия топологии (ASN Herfindahl-Hirschman Index)**:
  - Автоматический расчёт индекса концентрации автономных систем ($HHI \le 2500$).
  - Запрет концентрации сторожевых узлов в одной подсети или у одного оператора связи. Периметр охраняется разнородным пулом каналов.
- **Автономное самоисцеление периметра (Autonomous Self-Healing)**:
  - При выходе из строя или физическом уничтожении до 2 сторожевых постов из 6, оставшийся кворум за секунды реконструирует утраченные ключи доступа и журналы событий через алгоритм Рида-Соломона.

### 2. Суверенное Зашифрованное Хранилище (Zero-Knowledge Vault)
- **16 KB квантование (Micro-Chunking Engine)**: любые видеоархивы наблюдения, журналы доступа и конфиденциальные данные разрезаются на канонические блоки по ровно 16,384 байта.
- **Шифрование ChaCha20-Poly1305 (RFC 8439)**:
  - 256-битный симметричный ключ, выводимый из мастер-мнемоники BIP-39 владельца объекта.
  - 12-байтный уникальный nonce и 16-байтный аутентификационный тег Poly1305. Подделка даже одного байта видеозаписи или лога приводит к немедленному аппаратному алерту.
- **Избыточное кодирование Reed-Solomon 4+2 над $GF(2^8)$**:
  - Примитивный полином: `0x11D` ($x^8 + x^4 + x^3 + x^2 + 1$).
  - Матрица Вандермонда с коэффициентами `[1, 2, 4, 8]` для проверочных шардов.
  - Гарантия 100% восстановления информации при одновременной потере любых 2 из 6 узлов хранения.
- **Криптографический аудит Proof-of-Retrievability (PoR)**:
  - Непрерывный опрос узлов охраны случайными криптографическими вызовами $s \in \{0, 1\}^{256}$.
  - Дедлайн ответа: строго 3,000 мс. Пропуск вызова снижает репутацию ноды и запускает процедуру перестраховки сектора.

### 3. Скрытый Сетевой Протокол (P2P Wire Protocol)
- **Канонический бинарный стандарт (Big-Endian)**:
  - Описан в [PROTOCOL_WIRE_SPEC.md](PROTOCOL_WIRE_SPEC.md).
  - Единый 46-байтный заголовок: `Magic "NEXX" (4B)` + `Version 0x02 (1B)` + `Opcode (1B)` + `RequestId (4B)` + `PayloadLength (4B)` + `SHA-256 Checksum (32B)`.
  - Зафиксированные коды операций: `PING`, `PONG`, `NODE_ANNOUNCE`, `STORE_CHUNK`, `FETCH_CHUNK`, `POR_CHALLENGE`, `POR_RESPONSE`, `KAD_FIND_NODE`, `EPOCH_FINALIZE`, `SMP_ENVELOPE`.
- **Полная анонимность через Tor v3 Onion**:
  - Каждый охранный пост имеет 62-символьный `.onion` адрес, генерируемый детерминированно из 32-байтного Ed25519 публичного ключа.
  - Управление объектом не требует выделенного IP-адреса или проброса портов (NAT traversal из коробки). Трафик не пеленгуется внешними сканерами.
- **Kademlia 256-bit DHT с защитой от Sybil-атак**:
  - Метрика расстояния XOR над 256-битными ключами.
  - Калиброванный майнинг 14-битного Proof-of-Work перед допуском узла в таблицу маршрутизации.

## 🎯 Принцип 100% Совместимости и Единое Ядро (`nexxus-core`)

В проекте NeXXUs исключён подход «разные команды пишут похожую логику». Источником истины для всех платформ является **Единое Протокольное Ядро** на Rust, компилируемое в целевые бинарные интерфейсы:

```
                          ┌───────────────────────────┐
                          │   nexxus-core (Rust)      │
                          │ • BIP-39 & Ed25519 Keys   │
                          │ • ChaCha20-Poly1305 AEAD  │
                          │ • Reed-Solomon (4+2) GF256│
                          │ • Merkle PoR & Wire Spec  │
                          └─────────────┬─────────────┘
                ┌───────────────────────┼───────────────────────┐
                ▼                       ▼                       ▼
        UniFFI Bindings           WASM / napi-rs          WASM / Browser
      ┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
      │  Android Sentinel│    │   Linux Daemon   │    │  Web Operations  │
      │  (Kotlin/Compose)│    │ (Node.js/systemd)│    │ (React/Terminal) │
      └──────────────────┘    └──────────────────┘    └──────────────────┘
                ▲                       ▲                       ▲
                └───────────────────────┴───────────────────────┘
                     ВЕРИФИКАЦИЯ: nexxus-vectors/ (Golden Vectors)
```

### Эталонные Векторы (`nexxus-vectors/`)
Каждая математическая операция покрыта фиксированными JSON-векторами, гарантирующими побитовую идентичность:
- `01_bip39_seed.json` — деривация 512-битного сида (PBKDF2 HMAC-SHA512, 2048 раундов, официальный вектор Trezor #1).
- `02_tor_v3_onion.json` — расчет Tor v3 адреса (35 байт base32 = 56 символов + `.onion` = ровно 62 символа).
- `03_reed_solomon_gf256.json` — кодирование 16 KB чанка в 6 шардов и восстановление при стирании 2 шардов.
- `04_merkle_tree.json` — SHA-256 дерево над 5 чанками с дублированием нечетного листа и inclusion proof.
- `05_chacha20_poly1305.json` — RFC 8439 AEAD шифрование 16 KB чанка с аутентификационным тегом.

## 🚀 Быстрый Старт

### 1. Веб-Терминал Управления Охраной
```bash
# Клонирование репозитория
git clone https://github.com/nexxus-security/nexxus-network.git
cd nexxus-network

# Установка зависимостей
npm install

# Запуск локального терминала охраны (порт 3000)
npm run dev
```

### 2. Запуск Полного Пайплайна Тестов
```bash
# Запуск 108 протокольных тестов + верификация всех Golden Vectors
npm test

# Запуск только верификации эталонных векторов
npm run test:vectors

# Перегенерация эталонных векторов при обновлении спецификации
npm run vectors:gen
```

### 3. Развёртывание Сторожевого Демона на Linux (Ubuntu / Debian)
```bash
# Установка готового официального пакета
sudo dpkg -i public/packages/nexxus-node_latest_amd64.deb

# Или автоматическая установка из исходников с созданием службы systemd:
sudo bash scripts/install-ubuntu.sh

# Проверка статуса охраны и сторожевого демона
sudo systemctl status nexxus-node

# Запуск криптографического теста PoR с дедлайном 3000 мс
npm run linux:test-por

# Бенчмарк производительности локального хранилища
npm run linux:benchmark
```
