# NeXXUs Golden Protocol Test Vectors (`nexxus-vectors/`)

> **Принцип 100% совместимости протоколов**:  
> Протокол не реализуется повторно на каждой платформе как «похожая логика». Каждая реализация (Rust `nexxus-core`, Kotlin/Android, TypeScript Web/Daemon) обязана побайтово воспроизводить `expected_output_hex` для каждого вектора. Несовпадение хотя бы в 1 бит является блокирующим дефектом.

---

## Состав эталонных векторов (v1.0)

| Файл | Операция | Спецификация | Контрольное значение |
|---|---|---|---|
| `01_bip39_seed.json` | BIP-39 mnemonic → seed | 2048 раундов PBKDF2 HMAC-SHA512 со солью `mnemonic` + passphrase | 512-битный seed (128 hex chars) |
| `02_tor_v3_onion.json` | Ed25519 Pubkey → Tor v3 .onion | Base32(Pubkey[32] \|\| Checksum[2] \|\| Version 0x03) + `.onion` | 56 base32 символов + `.onion` (всего 62 символа) |
| `03_reed_solomon_gf256.json` | Reed-Solomon (4+2) над $GF(2^8)$ | Примитивный полином `0x11D`, 4 блока данных + 2 блока четности (P1=XOR, P2=Vandermonde [1,2,4,8]) | 100% побайтовое восстановление 16KB чанка при потере любых 2 шардов |
| `04_merkle_tree.json` | SHA-256 Merkle Tree & Audit Proof | Двоичное дерево с дублированием последнего листа при нечетности | Корень дерева, аудит-доказательство для индекса 2 |
| `05_chacha20_poly1305.json` | ChaCha20-Poly1305 AEAD | RFC 8439 (256-bit key, 96-bit nonce, 128-bit Poly1305 tag) | Точный шифротекст и аутентификационный тег |

---

## Правила участия для платформ

1. **Rust Core (`nexxus-core`)**: прямое использование crate в качестве первоисточника.
2. **Kotlin (Android)**: биндинги через `uniffi-rs` либо прохождение тестов против файлов из этой директории.
3. **TypeScript / Web / Node.js**: запуск автотестов через `npm test` (`test/golden-vectors.test.ts`).
4. **Запрет односторонних правок**: изменение формата или значений в файлах векторов допускается ТОЛЬКО при взаимном согласовании всех сторон (Клод, Женя, Гриша) с обновлением `expected_output_hex`.
