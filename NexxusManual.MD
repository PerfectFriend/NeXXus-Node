# NeXXUs Protocol: Подробное Руководство по Эксплуатации
### Версия 2.0.0 (Production Release & Operations Manual)

> **Для кого этот документ:**
> 1. **Для пользователей:** Как пользоваться нерушимым Сейфом (Vault), загружать файлы, управлять BIP-39 ключами, обмениваться сообщениями через Tor v3.
> 2. **Для системных администраторов:** Установка и запуск пакета `nexxus-node_2.0.0_amd64.deb`, интеграция с `systemd`, мониторинг, тюнинг NVMe дисков и тестирование межхостового взаимодействия.
> 3. **Для разработчиков ядра:** Сохранение структуры тестового стенда, отладочных механизмов и протокола верификации.

## 1. РУКОВОДСТВО ДЛЯ ПОЛЬЗОВАТЕЛЯ

### 1.1. Концепция нулевого доверия и суверенитета
В NeXXUs нет учетных записей, паролей, серверов авторизации Google или номеров телефонов:
- **Ваша личность** — это мнемоническая фраза из 12 слов по стандарту **BIP-39**.
- **Ваши файлы** шифруются ключом **ChaCha20-Poly1305** прямо в браузере или на клиенте до отправки в сеть.
- **Ни один узел в мире** (даже те, на которых физически лежат куски вашего файла) не может узнать имя файла, его размер или его содержимое.

### 1.2. Бартерный договор: «16 ГБ диска ➔ 2 ГБ Сейфа»
- Чтобы получить **2.0 ГБ** защищенного нецензурируемого хранилища в облаке NeXXUs, вам достаточно выделить **16 ГБ** свободного места на любом вашем устройстве (ноутбук, старый телефон на Android, домашний mini-PC).
- Если вы выделяете больше места (например, 48 ГБ или 384 ГБ), за каждую дополнительную секцию по 16 ГБ ваш личный Сейф увеличивается пропорционально:
  $$\text{Квота Сейфа (ГБ)} = 2.0 + \frac{\text{Выделено сверх 16 ГБ}}{8}$$
- Также за реальное хранение чужих данных на расширенных секциях начисляются токены **$NEXX**.

### 1.3. Пошаговая работа с файлами
1. **Первый вход:** Откройте веб-интерфейс и нажмите на кнопку **«BIP-39 Ключ»** в правом верхнем углу. Запишите 12 слов на бумагу. Это ваш единственный ключ восстановления.
2. **Загрузка файла:** Перейдите во вкладку **«Приватное Облако (1/8)»**. Перетащите файл в область загрузки. Файл:
   - Зашифруется симметричным ключом ChaCha20-Poly1305 прямо на вашем устройстве.
   - Разобьется на 16-килобайтные чанки.
   - **По умолчанию в MVP-A (смартфоны)**: реплицируется по схеме **RF=6×** (6 копий с уникальным per-node шифрованием, не требуя энергозатратных матричных вычислений от телефонов).
   - **Для десктопных нод и V2**: доступно сжатие **Рида-Соломона (4+2)** над $GF(2^8)$ (4 блока данных и 2 блока четности) с экономией места.
   - Разлетится по независимым onion-нодам сети с контролем ASN-диверсификации.
3. **Скачивание файла:** Нажмите «Скачать» рядом с любым файлом. Клиент запросит чанки у ближайших пиров сети. Даже если **любые 2 ноды из 6 выключены** (при RS 4+2) или до 5 нод временно недоступны (при RF=6×), файл мгновенно восстанавливается без потерь.
4. **Анонимный мессенджер:** Во вкладке **«SMP/xFTP Мессенджер»** вы можете обмениваться зашифрованными сообщениями напрямую через Tor v3 скрытые сервисы (.onion) без передачи метаданных.

## 2. РУКОВОДСТВО ДЛЯ СИСТЕМНОГО АДМИНИСТРАТОРА

### 2.1. Описание дистрибутива и архитектура сборки
Для серверов и рабочих станций под управлением **Ubuntu 20.04 / 22.04 / 24.04 LTS (amd64)** или **Debian 11/12** подготовлен пакет:
- **Архитектура сборки**: TypeScript демон (`scripts/linux-daemon.ts`), скомпилированный `esbuild` в единый автономный CJS-бандл (`dist/nexxusd.cjs`, 252 КБ) и упакованный в стандартный `.deb` архив.
- **Имя файла:** `nexxus-node_2.0.0_amd64.deb`
- **Размер архива:** ~51 КБ (сжатие dpkg-deb / gzip)
- **Установленный размер:** ~258 КБ
- **Рантайм-зависимость:** `nodejs (>= 18.0.0)`
- **Пользователь службы:** `nexxus:nexxus`
- **Каталог данных и базы чанков:** `/var/lib/nexxus`
- **Каталог системных логов:** `/var/lib/nexxus/logs`
- **Исполняемый файл / лаунчер:** `/usr/bin/nexxusd` (POSIX shell wrapper к `/usr/lib/nexxus/nexxusd.cjs`)
- **Служба systemd:** `/etc/systemd/system/nexxus-node.service`
- **Режим разработки:** прямой запуск без сборки через `npx tsx scripts/linux-daemon.ts`

### 2.2. Установка в одну команду
```bash
# 1. Скачать и установить .deb пакет
sudo dpkg -i nexxus-node_2.0.0_amd64.deb

# Если отсутствуют зависимости (например, nodejs >= 18):
sudo apt-get install -f -y

# 2. Активировать и запустить фоновую службу
sudo systemctl enable --now nexxus-node

# 3. Проверить статус демона
sudo systemctl status nexxus-node
```

### 2.3. Конфигурация узла (`/etc/nexxus/nexxus.conf`)
Конфигурационный файл создается автоматически при установке:
```ini
# /etc/nexxus/nexxus.conf
NODE_PORT=3999
STORAGE_PATH=/var/lib/nexxus
# Выделенный объем под хранилище (в ГБ, кратно 16)
ALLOCATED_GB=384
MAX_PEERS=50
LOG_LEVEL=info
ENABLE_TOR=true
BOOTSTRAP_PEERS=seed1.nexxus.network:3999,seed2.nexxus.network:3999
```

После изменения конфигурации перезапустите службу:
```bash
sudo systemctl restart nexxus-node
```

### 2.4. Справочник команд CLI (`nexxusd`)

| Команда | Описание |
| :--- | :--- |
| `nexxusd status` | Вывод сводки: Node ID, Tor .onion адрес, выделенный пул, аптайм, количество чанков. |
| `nexxusd benchmark` | Тестирование случайного блочного I/O (16KB) на диске и замер IOPS. |
| `nexxusd test-por` | Запуск локального теста Proof-of-Retrievability (должен отвечать `< 3000 ms`). |
| `nexxusd test-interhost <IP:PORT>` | Сквозное 6-фазное P2P тестирование против другого сервера в сети. |
| `nexxusd upload <FILE>` | Шифрование файла, нарезка на 16KB чанки и отправка пирам по Reed-Solomon. |
| `nexxusd download <HASH> <OUT>` | Скачивание и сборка файла по его Merkle/Content Hash. |
| `nexxusd logs` | Вывод последних 100 строк системного журнала демона. |

### 2.5. Мониторинг и просмотр логов
Для отслеживания сетевой активности, PoR аудитов и входящих чанков в реальном времени:
```bash
journalctl -u nexxus-node -f -n 50
```

## 3. МЕЖХОСТОВОЕ ТЕСТИРОВАНИЕ (2 ХОСТА)

Сценарий валидации взаимодействия двух независимых серверов (Хост A и Хост B):

1. **На Хосте A (192.168.1.10):**
   ```bash
   sudo systemctl start nexxus-node
   nexxusd status
   ```
2. **На Хосте B (192.168.1.20):**
   ```bash
   # Выполнить сквозную 6-фазную проверку Хоста A
   nexxusd test-interhost 192.168.1.10:3999
   ```
3. **Что проверяется автоматически:**
   - **Фаза 1: ASN & Topology Lookup** — проверка независимости автономной системы BGP.
   - **Фаза 2: Wire PING/PONG (0x01)** — валидация бинарного протокола сокетов и замер RTT.
   - **Фаза 3: Kademlia DHT (0x03)** — поиск ближайших узлов по XOR метрике.
   - **Фаза 4: 16KB Shard Store (0x10)** — передача шифрованного чанка на NVMe диск Хоста A.
   - **Фаза 5: Shard Fetch & Parity (0x12)** — обратное чтение и сверка SHA-256 хэша байт-в-байт.
   - **Фаза 6: PoR Challenge (0x20)** — субсекундный криптографический аудит дискового владения.

## 4. СТРАТЕГИЯ ЧИСТКИ И РЕЛИЗА (PRODUCTION vs DEBUG)

По вашему указанию:
1. **Для финального продакшн-релиза:**
   - Из публичного пользовательского интерфейса убираются временные генераторы случайных чанков и синтетические таймеры симуляции.
   - Логирование демона переводится в режим `INFO`/`WARN` (без спама в syslog).
   - Все отладочные комментарии минифицируются сборщиком `esbuild` с флагами `--drop:console` и `--minify`.
2. **Для внутренней команды разработчиков (Debug Platform):**
   - Полный тестовый стенд (`test/protocol.test.ts` со всеми 108 тестами) сохраняется в репозитории.
   - Дополнительные модальные лаборатории (Kademlia Engine Lab, Erasure Coding Lab, Soak Test Dashboard, Grok Simulation Lab) остаются доступными через инженерные маршруты для непрерывной интеграции и тестирования новых релизов.

## 5. АВАРИЙНЫЕ СИТУАЦИИ И ВОССТАНОВЛЕНИЕ (DISASTER RECOVERY)

1. **Сервер внезапно выключился (пропало питание):**
   - У вас есть **1 час льготного периода (Grace Period)**.
   - При включении служба `nexxus-node` поднимется автоматически через systemd.
   - Все локальные чанки проверяются по Merkle Root и возвращаются в активную таблицу Kademlia без штрафов.
2. **Сгорел системный диск:**
   - Установите ОС заново, поставьте пакет `nexxus-node_2.0.0_amd64.deb`.
   - Введите вашу 12-словную мнемоническую фразу BIP-39 в конфигурацию:
     ```bash
     nexxusd restore-identity "слово1 слово2 ... слово12"
     ```
   - Ваши персональные файлы Сейфа будут автоматически скачаны из распределенной сети других участников роя.
