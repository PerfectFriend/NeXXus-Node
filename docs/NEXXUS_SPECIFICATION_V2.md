# ТЕХНИЧЕСКОЕ ЗАДАНИЕ И ПОЛНАЯ СПЕЦИФИКАЦИЯ ПРОТОКОЛА NEXXUS v2.0
## Sovereign Decentralized Cryptophone OS, Storage Swarm & Onion P2P Mesh
*Стандарт совместимости для альтернативных реализаций (Grok, Claude Opus, Nvidia Nemotron Ultra)*

---

## 1. АРХИТЕКТУРНЫЙ ОБЗОР И ФИЛОСОФИЯ СИСТЕМЫ

**NeXXus** — это децентрализованная одноранговая (P2P) операционная среда и сеть суверенного хранения данных, разработанная для работы на специализированных криптофонах и мобильных устройствах вторичного рынка (старые смартфоны Android, нетбуки, одноплатные компьютеры).

### Базовые принципы:
1. **Zero-Server Architecture**: Полное отсутствие централизованных серверов, баз данных, трекеров и сторонних облачных провайдеров (AWS, Cloudflare, Google Cloud).
2. **Onion v3 Routing by Default**: Вся P2P-коммуникация и передача чанков данных маршрутизируется через скрытые сервисы Tor v3 (`*.onion:9050`) либо прямые пиринговые туннели WireGuard с шифрованием ChaCha20-Poly1305.
3. **Криптографическая суверенность (BIP-39)**: Единая мнемоническая сид-фраза генерирует все ключи аутентификации, адреса узлов, ключи шифрования личного сейфа и балансы встроенного DEX.
4. **Антипыточный анклав (Panic Duress PIN)**: Поддержка двух раздельных PIN-кодов с экспоненциальным удвоением кулдауна при ошибках и скрытой загрузкой фальшивого (decoy) профиля при принудительном вводе Panic PIN.
5. **Строгая мобильная эргономика (Single-Screen Discipline)**: Все экраны приложения, за исключением содержимого списков, обязаны полностью помещаться в один экран устройства без внешней прокрутки страницы (`overscroll-behavior: none`, `overflow: hidden`). Прокручиваются только внутренние окна списков.

## 2. КРИПТОГРАФИЧЕСКИЙ СТЕК И СТАНДАРТЫ ИДЕНТИФИКАЦИИ

### 2.1. Генерация мнемоники (BIP-39)
- **Энтропия**: 128 бит (для 12 слов) либо 256 бит (для 24 слов) из CSPRNG (`crypto.getRandomValues`).
- **Словарь**: Официальный английский словарь BIP-39 (2048 слов).
- **Контрольная сумма**: SHA-256 хэш энтропии (первые 4 бита для 128 бит энтропии).
- **Derivation Seed**: PBKDF2 с HMAC-SHA512 (2048 итераций, соль `"mnemonic" + passphrase`).
- **Деривационный путь HD-кошелька**:
  ```
  m/44'/999'/0'/0/0
  ```
  - `44'` — стандарт BIP-44.
  - `999'` — зарегистрированный Coin Type сети NeXXus.
  - `0'` — основной аккаунт.

### 2.2. Криптографические примитивы
- **Цифровые подписи**: Ed25519 (RFC 8032) — используются для подписи транзакций, аутентификации в сети и подтверждения хранения чанков (PoR).
- **Обмен ключами (Key Exchange)**: X25519 (RFC 7748, Curve25519) — используется для асимметричного согласования сессионных ключей в протоколах SMP и xFTP.
- **Симметричное шифрование**: ChaCha20-Poly1305 AEAD (RFC 8439) с 256-битным ключом и 96-битным уникальным nonce.
- **Хэширование**: 
  - SHA-256 (FIPS 180-4) для контрольных сумм блоков и PIN-хеширования.
  - BLAKE3 / SHA-256 для построения деревьев Меркла файлов.

### 2.3. Форматы адресов сети
1. **NeXXus Account Address**:
   - Префикс: `nx1q`
   - Кодирование: Bech32
   - Полезная нагрузка: RIPEMD160(SHA-256(Ed25519_PublicKey))
   - Пример: `nx1q9f7x4a2e8w3u1s0d6c8b5m2k4p7z9l3j5h`
2. **Tor Onion v3 Address**:
   - 56 символов Base32 + `.onion:9050`
   - Вычисляется детерминированно из Ed25519 публичного ключа скрытого сервиса.

## 3. СЕКЦИОННОЕ ХРАНИЛИЩЕ ДАННЫХ И ЭКОНОМИКА БАРТЕРА

### 3.1. Квантование хранилища по 16 ГБ
- Хранилище любого устройства в сети NeXXus делится на фиксированные неделимые **Секции по 16 ГБ**.
- Смартфон с 64 ГБ памяти выделяет 3 секции (48 ГБ), ноутбук с 512 ГБ SSD может выделить 20–30 секций.

### 3.2. Базовое правило бартера (16 ГБ -> 2 ГБ)
- Выделение первой базовой секции 16 ГБ в пользу сети предоставляет пользователю право на **2.0 ГБ неуничтожимого личного облачного хранилища**, реплицируемого на других нодах роя.
- Оставшиеся 14 ГБ первой секции отдаются под хранение чужих шардов.

### 3.3. Коэффициент расширения (Правило 1/8)
- За каждую последующую выделенную сеть секцию 16 ГБ личная квота пользователя увеличивается на:
  $$\Delta \text{Quota}_{\text{personal}} = 16 \text{ ГБ} \times \frac{1}{8} = 2.0 \text{ ГБ}$$
- **Формула расчета персональной квоты**:
  $$\text{Quota}_{\text{vault}} = 2.0 + (N_{\text{sections}} - 1) \times 2.0 \text{ [ГБ]}$$
  *(где $N_{\text{sections}} \ge 1$)*

### 3.4. Принцип "Оплата только за занятое" (Zero-Empty Payout)
- **Критическое правило сети**: Сеть NeXXus выплачивает вознаграждение майнинга **только за фактически размещенные чужие зашифрованные чанки**, и не платит за пустое зарезервированное пространство!
- **Формула суточного дохода ноды**:
  $$\text{Income}_{\text{daily}} = \text{ForeignChunksStored}_{\text{GB}} \times 1.25 \text{ NEXX}$$
- Если нода выделила 48 ГБ (3 секции), из которых сеть использует 21.8 ГБ под чужие шарды, а 10.2 ГБ остаются свободными — оплачиваются ровно 21.8 ГБ.

### 3.5. Вестинг наград storer (Anti-Sybil Lock 56 дней)
- Заработанные токены NEXX за хранение чужих данных блокируются в линейном вестинг-контракте на **8 недель (56 дней)**.
- Цель: предотвратить мгновенный сброс токенов атакующими, стимулируя долгосрочную непрерывную доступность нод.

## 4. СЕТЕВЫЕ ПРОТОКОЛЫ И СТЕК СВЯЗИ

### 4.1. Протокол SMP (Simple Messaging Protocol)
- **Назначение**: Безопасный асинхронный обмен сообщениями между контактами без серверов.
- **Шифрование**: Double Ratchet (аналог Signal/Element) поверх Onion v3 контура.
- **Формат пакета SMP**:
  ```json
  {
    "proto": "NEXXUS_SMP/1.2",
    "msg_id": "hex(sha256(nonce + ciphertext))",
    "timestamp": 1729170000000,
    "sender_onion": "sender...onion:9050",
    "recipient_onion": "recipient...onion:9050",
    "ratchet_pubkey": "hex(X25519_Ephemeral)",
    "iv": "hex(96_bit_nonce)",
    "ciphertext": "base64(encrypted_payload)",
    "auth_tag": "hex(poly1305_tag)"
  }
  ```

### 4.2. Протокол xFTP (Chunk Transport Protocol)
- **Назначение**: Передача зашифрованных блоков файлов по 16 КБ между нодами.
- **Размер чанка**: Строго **16 384 байта** (16 КБ).
- **Фактор репликации**:
  - Hot Storage Tier: $RF = 6$ (6 независимых нод с разными ASN).
  - Cold Archive Tier: $RF = 4$.
- **Структура Merkle-дерева файла**:
  - Листья: $H_i = \text{BLAKE3}(\text{Chunk}_i)$.
  - Корень: $H_{\text{root}} = \text{MerkleRoot}(H_0, H_1, \dots, H_{n-1})$.

### 4.3. Proof-of-Retrievability (PoR) и сброс штрафов
- Сеть каждые 6 часов генерирует псевдослучайный челлендж:
  $$\text{Challenge} = \text{HMAC-SHA256}(\text{EpochSeed}, \text{NodeId})$$
- Нода обязана предоставить доказательство Меркла для случайно выбранного листа хранящегося чанка.
- **Штрафы за простой (Slashing)**:
  - Простой > 24 часов: заморозка наград за текущую эпоху.
  - Простой > 14 дней: статус `warning_14d`, запуск алгоритма аварийного самовосстановления чанков на других узлах.
  - Простой > 28 дней: сжигание невыплаченного вестинга, репликация переносится в архивный пул.
- **Сброс штрафа**: Выполняется процедурой `ResetDowntimePenalty()` при повторном установлении онлайн-бриджа и успешном прохождении 3 последовательных раундов PoR.

## 5. БЕЗОПАСНОСТЬ: АНТИПЫТОЧНЫЙ АНКЛАВ И PANIC PIN

### 5.1. Двойной PIN-код
1. **Основной PIN (Primary PIN)**:
   - Длина: 4–6 цифр.
   - Разблокирует реальный криптографический анклав, личные секретные файлы, ключи и балансы кошелька.
2. **Панический PIN (Panic / Duress PIN)**:
   - Обязан отличаться от Основного PIN.
   - Вводится под принуждением или давлением третьих лиц.
   - **Поведение Panic PIN**:
     - Бесшумно и неотличимо от нормального входа переключает приложение в режим **Decoy Mode**.
     - Отображает нулевые балансы либо мизерные демонстрационные суммы.
     - Отображает безобидные файлы-приманки (инструкции, нейтральные pdf-файлы).
     - Блокирует доступ к настоящему мастер-ключу BIP-39 в памяти.

### 5.2. Экспоненциальное удвоение кулдауна при ошибках
При вводе неверного PIN-кода включается аппаратная задержка:
$$T_{\text{cooldown}}(n) = 5 \times 2^{n-1} \text{ [секунд]}$$
- 1-я ошибка: 5 секунд.
- 2-я ошибка: 10 секунд.
- 3-я ошибка: 20 секунд.
- 4-я ошибка: 40 секунд.
- 5-я ошибка: 80 секунд (и далее).
Во время кулдауна цифровой ввод блокируется, таймер отображается на экране.

## 6. СПЕЦИФИКАЦИЯ МОБИЛЬНОГО ИНТЕРФЕЙСА (UX/UI Constitution)

1. **Правило One-Screen**:
   - Никаких внешних полос прокрутки страницы на смартфонах.
   - `html, body, #root`: `height: 100%; height: 100dvh; overflow: hidden; overscroll-behavior: none;`.
2. **Изолированная прокрутка списков**:
   - Элементы управления, слайдеры, сводки балансов, карточки предупреждений и заголовки имеют класс `shrink-0`.
   - Контейнеры списков (чаты, файлы, узлы роя, стакан DEX) имеют класс:
     ```css
     flex: 1 1 0%;
     min-height: 0;
     overflow-y: auto;
     -webkit-overflow-scrolling: touch;
     ```
3. **Навигация**:
   - Главный экран — E2EE Мессенджер.
   - Переход в Персональный сейф — через пункт «⭐️ Избранное» в списке диалогов.
   - Все остальные модули (Секции хранилища, Флот устройств, dApp Store, DEX, Сетевые настройки, Спецификация) открываются через выезжающее боковое меню (Drawer).
   - Присутствует кнопка мгновенного сворачивания и блокировки приложения (Quick Lock).
